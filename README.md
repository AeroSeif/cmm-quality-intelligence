CMM Quality Intelligence Platform

Why I developed this

While working as an Overhaul Manufacturing Engineer at the Arab Organization for Industrialization (AOI), I realised that we needed to improve our measurement repeatability capabilities and make better use of the inspection data being generated by our CMM processes.

A significant part of this is being able to assess measurement consistency, identify characteristics that are approaching their allowable limits, and make inspection results easier to review. Having this information organised and analysed properly can reduce manual work and make it easier for engineers to identify potential issues.

This project grew out of that requirement.

The implementation used within AOI is separate from the application presented in this repository. The internal version was authorised by the Operations Manager and integrated with the organisation's internal database. This repository contains a demonstration version of the application, developed using Python and Streamlit, to show its functionality and the engineering approach behind it.

The intention is to make CMM inspection data easier to work with, rather than having engineers manually review multiple inspection reports and calculate the relevant statistics themselves.

What the application does

The application accepts Excel inspection workbooks, extracts the measurement records, checks the data for inconsistencies and presents the results through an interactive dashboard.

There are two separate analysis options.

1. Dynamic Repeatability

This study deals with repeated measurements of the same physical component.

Multiple inspection workbooks are processed and the dimensional measurements are grouped by characteristic. The application calculates:

Mean measured value.

Sample standard deviation.

Observed measurement range.

Six-standard-deviation study variation (6s).

Repeatability as a percentage of the total tolerance.

Utilisation of the applicable repeatability acceptance limit.

The results are presented using a colour-coded dashboard, allowing characteristics that are approaching or exceeding their applicable limits to be identified more easily.

The analysis uses configurable Critical, Major and Minor classification limits. The implementation currently uses 10%, 20% and 30%, respectively. These values must be checked against the applicable customer requirements and approved standard revision before any engineering use.

2. Part Variation

This study uses measurements from different manufactured components. Unlike repeatability analysis, the objective here is to understand how the measured dimensions vary between parts.

The application presents:

Mean and standard deviation for each characteristic.

Minimum and maximum measured values.

Observed dimensional spread.

Out-of-specification measurement counts.

Measurement distributions and boxplots.

A Pareto chart ranking characteristics by out-of-specification readings.

Repeatability acceptance criteria are not applied to this study. Process capability analysis, including Cp and Cpk, is a separate development item and requires suitable process data and study conditions.

Input data

The demonstration application accepts one or more Excel inspection workbooks (.xlsx and .xlsm).

The current extraction engine is designed around the established inspection workbook structure. It reads the Inspection Report worksheet and extracts the following information where available:

Characteristic identifier.

Nominal dimension.

Actual measured dimension.

Measurement error.

Upper and lower specification limits.

Dimensional pass/fail result.

Actual geometric tolerance.

Geometric tolerance limit and pass/fail result.

Dimensional and geometric measurements are kept separate because they require different analysis methods.

The application also performs validation checks, including missing values, invalid tolerance limits, measurement calculation inconsistencies and differences in characteristic specifications between reports.

Note: The current version expects the defined workbook structure. It is not yet a universal parser for every CMM software export format.

Demonstration datasets

Two synthetic datasets are included in the repository:

Data/Repeatability/ — repeated inspection runs of the same simulated component.

Data/Part_Variation/ — inspection reports representing different simulated components.

These datasets are intended for testing and demonstrating the application. They do not represent actual AOI production measurements or customer inspection records.

The demonstration data can be regenerated using generate_synthetic_data.py, with fixed seeds for reproducible tests or random seeds for new datasets.

Running the application locally

Python 3.11 is recommended for the current dependency configuration.

Create a virtual environment, install the dependencies and start the application:

python -m venv .venv

# Windows PowerShell
.venv\Scripts\Activate.ps1

pip install -r requirements.txt

streamlit run app.py

The application loads the included demonstration data automatically. There is no need to generate the datasets or run the separate analysis script before opening the website.

Deployment

The public demonstration is deployed through Streamlit Community Cloud and connected to this GitHub repository.

The application can be accessed directly through the live link above. Visitors do not need to install Python or download the repository.

Changes pushed to the selected GitHub branch are reflected in the deployed application.

Technical stack

Python — application logic and statistical calculations.

Streamlit — interactive web application.

Pandas and NumPy — inspection data processing and numerical calculations.

OpenPyXL — Excel workbook extraction and reporting.

Plotly — interactive charts and visualisations.

Pytest — automated testing.

Further development and production considerations

The public application is a demonstration of the approach, not the internal AOI implementation.

The next stages of development include extending the supported CMM export formats, improving the statistical reporting, and developing more detailed quality analysis capabilities.

Any deployment using actual production measurements must remain within an organisation-approved environment. This requires appropriate data access controls, audit trails, backups, controlled calculation configurations, software verification and validation, and formal engineering approval.

The dashboard results should not be treated as an authorised product-release decision without the applicable approved procedures and acceptance requirements.

Developed as an engineering project based on practical experience in aerospace overhaul manufacturing and dimensional inspection.
